## Concrete causes and fix order

### First: #678

`apps/shadcn-registry/src/lib/wallet-kit/providers/privy/PrivyPluginProvider.tsx:148` publishes a synthetic embedded session with `chainId: selectedEvmChainId`. `runtime/evm/wallet-runtime.ts:274` then treats the synthetic connection's old chain as external truth and writes it back into preferences. The embedded-source effect concurrently republishes the newly selected preference. An experiment using the actual registry reducer and extracted synchronization effect alternated preference/registry between Ethereum and Arbitrum for eight modeled effect batches.

Proposed minimal change: skip reverse synchronization for `kind === "embedded-session"`; keep synchronization for genuinely observed external connector changes. Add a mounted provider/runtime regression proving bounded updates, successful/cancelled switches and rapid changes. The experiment models scheduling; it is not a React harness. The live minified crash frame resolves to Radix FocusScope composed-ref state setters, which may be downstream of repeated renders and does not independently identify the originating wallet effect.

### Second: #679 + #680

`providers/privy/PrivyPluginProvider.tsx:279` omits `canSignFor`. `composer/AomiWalletKitComposer.tsx:148` requires that callback to return true for every embedded EVM/SVM connection. `composer/wallet-state.ts:161` therefore keeps even exact matching linked wallets loading; `:203` excludes them from operating identity. `composer/build-identity.ts:30` and `wallet-kit/context.tsx:88` consequently have no eligible wallet address to synchronize into chat.

Implement `canSignFor` against the actual hydrated exact-address signer paths: embedded EOA, hydrated smart client account, and selected Solana signer. Authentication alone must not imply signing readiness. Distinguish transient hydration from terminal unavailable/error state and show the actual waiting/failing layer. Verify SDK hydration, mismatched addresses, disconnect, account/provider changes, smart-wallet identity and external connector coexistence. Check the submitted chat user-state addresses as well as agent prose.

Related [#421](https://github.com/aomi-labs/aomi/issues/421) remains a separate external-plus-embedded permit-routing scenario. Current shared typed-data signing already passes an explicit signer/account and Privy already has an embedded EOA typed-data implementation; the old no-account claim is stale. However, an active external signer suppresses the embedded override and target-account provider routing remains absent. Fixing readiness alone does not promise to fix #421. Resolve the requested wallet's signer independently of ambient connector and preserve backend wrong-signer checks.

### Small FE fixes: #681 and Base Sepolia in #683

`features/usage/statement-api.ts:184` sets `onchainNote: ""`; `features/usage/usage-shared.tsx:697` always emits the sentence. Guard the entire clause when empty; avoid inventing a fee amount or payer.

`components/icons/chain-map.tsx:16` lacks chain 84532. The selector falls back to the first two ticker characters, explaining ET. Base's square is intentional and supported by [official Base identifiers](https://brand.base.org/core-identifiers); Sepolia's T is an intentional testnet badge.

### #685: split into separate concerns

`packages/client/src/guest-auth.ts:46` deliberately leaves a possibly existing signed-in cookie intact on the first request. `packages/client/src/client.ts:242` retries the same request once after anonymous authentication on a 401. Existing regression coverage documents the design. This is not a silent alternate chat transport.

Avoidable account callers are `account-shell/lib/account-overview.ts:179`, `account-shell/components/providers/aomi-session-bridge.tsx:90`, and `apps/portal/src/features/general/use-svm-wallet-binding.ts:42`. Gate by a real account and actual binding need; preserve genuine login transition retry semantics.

The EVM connector configuration is already memoized/cached. Privy's own WalletConnect support plus Aomi's connector is a plausible second owner, not a proven cause. Capture the initialization owner/stack before changing ownership; do not merely add another memo or suppress the warning.

### Product choices: #682, #684, #686

Swig discovery currently uses a deliberate disabled-feature failure. Return typed availability if error-free discovery is desired; 204 alone would break the current JSON caller. Source does not establish that the frontend knows availability before fetching.

Portal opts into `aui-suggestions-marquee` in `portal-aomi-frame.tsx:359`; `themes/default.css:422` explicitly masks/animates it. Existing non-marquee suggestions wrap. Removing the opt-in is the smallest readability change; test keyboard activation, mobile, reduced motion and composer layout.

`assistant-ui/thread-list.tsx:199` contains only Archive. Rename already flows through `packages/react/src/runtime/threadlist-adapter.ts:126` to `packages/client/src/agent/transport.ts:216`. Add UI with trimmed title validation, Enter/save, Escape/cancel, failure feedback/rollback and correct unsaved-chat behavior. The adapter currently catches failed writes, so the UI needs an observable failure signal.
