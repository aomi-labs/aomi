# Guest Chat browser regression

After `pnpm install --frozen-lockfile` and `pnpm exec playwright install chromium`, run `pnpm run test:browser:guest`. The command fails if Docker, Chromium, package builds, Portal build, readiness, or either required test is missing or fails. It starts disposable Postgres, migrates only Better Auth's schema, builds the frontend packages and Portal, and cleans up its owned Postgres and Portal processes. Failure artifacts are under `output/playwright/`: a sanitized Portal log, Playwright JSON, trace, screenshot, video, and HTML report. CI uploads the same artifacts and includes this job in **Frontend CI Passed**.

The send/reload journey renders the real production Portal, widget shell, React runtime, and SDK client in Chromium. Playwright intercepts browser `/api` and `/v1` traffic for that journey and supplies a deterministic guest cookie and Agent event ledger. It verifies one settled reply, a persisted thread, recovery of the same messages after refresh, and isolation from a second guest. These mocks do **not** verify the Rust runtime, a model provider, or Better Auth's database behavior.

The other Playwright check sends HTTP requests to the real Portal auth route backed by disposable Postgres. It verifies that the Portal's own origin reaches OAuth request validation while an unregistered origin receives `origin_not_allowed`. Focused `principal.test.ts` cases cover immutable-preview guest cookies, unregistered origins, CSRF, account/session scope, and widget origin binding. Exact-deployment previews with real services still need a post-PR manual send/reload smoke because model and backend availability are independent of this deterministic suite.
