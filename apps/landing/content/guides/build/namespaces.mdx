# Apps and authentication

An Aomi **App** is the deployed unit users select. Builders author a Rust plugin; the deployment makes it available to Agent and Pipeline callers.

These boundaries are independent:

| Boundary         | What it controls                                                    |
| ---------------- | ------------------------------------------------------------------- |
| Caller identity  | Which guest or account owns a call or Agent session.                |
| App selection    | Which App handles Direct work, or whether Auto routing chooses one. |
| App access       | Whether the caller may use the selected App.                        |
| App credentials  | User-owned secret slots declared by one App.                        |
| Wallet authority | Which exact Action a wallet can review and sign.                    |

## Auto and Direct

Agent uses Auto routing by default. Select Direct only when you mean to pin one App:

```bash
aomi chat "compare routes" --new-session
aomi chat "quote this swap" --mode direct --app zerox --new-session
aomi chat "use this hosted App" --application-id 2936682 --new-session
```

Use the canonical numeric Application ID when a hosted App name can be ambiguous. Pipeline is already explicit:

```bash
aomi pipeline apps
aomi pipeline operations --app aave
```

## Caller identity and App access

Guest or OAuth credentials establish caller identity. OAuth grants bind to exact resources such as `/v1/agent`, `/v1/pipeline`, and `/v1/account`; their tokens are not interchangeable.

Some provisioned Apps also require an App access key. The TypeScript client's `apiKey` option and the CLI's `--api-key` flag send it as `Aomi-App-Key`.

```bash
aomi chat "run the selected App" \
  --mode direct \
  --app my-app \
  --api-key "$AOMI_API_KEY"
```

Do not use retired `X-API-Key`, `/api/chat`, or query-string message examples. Current Agent work uses the versioned `/v1/agent` resource.

## User credentials

Persistent App credentials are declared slots owned by one account and App. Status calls return slot names and configuration state, never saved values. Merged client `0.9.4` source adds hidden-input CLI commands:

```bash
aomi app credentials status <application-id>
aomi app credentials set <application-id> EXCHANGE_API_KEY
```

These commands require a matching npm release and Account API deployment. npm `latest` is `0.7.6` as of September 22, 2026.

Temporary `aomi secret add NAME=value` handles and model-provider BYOK keys are separate stores with different lifetimes.

## Sessions and wallets

An Agent session continues a conversation and belongs to its authenticated caller. A session ID, wallet address, or App key is not an authentication credential.

Wallet context tells the App which account to build for. Signing still requires review of the exact pending Action.

Read the canonical [Apps and authentication reference](https://aomi.dev/docs/reference/apps-and-authentication) for the full identity model and [Transactions and signing](https://aomi.dev/docs/reference/client-cli/transactions-and-signing) for wallet execution.
