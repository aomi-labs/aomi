# Building Apps

An Aomi App is a packaged Rust plugin that gives the hosted Agent runtime a
preamble and a set of typed tools. You implement the plugin with the public
`aomi-sdk` crate; the host owns model orchestration, sessions, authorization,
action review, and event delivery.

## App components

| Component                     | Purpose                                                     |
| ----------------------------- | ----------------------------------------------------------- |
| Preamble                      | Define the App's role, rules, and expected workflow         |
| `DynAomiTool` implementations | Expose typed operations to the model                        |
| Secret declarations           | Name operator-owned configuration or user-owned credentials |
| Host namespaces               | Request the platform capabilities the tools call            |
| Manifest                      | Register the App name, version, tools, and capabilities     |

## Create the plugin

Pin the SDK version you build and test:

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
aomi-sdk = "=5.1.1"
serde = { version = "1", features = ["derive"] }
```

Define one typed argument structure and one `DynAomiTool` implementation for
each operation. Keep tool descriptions specific enough for the model to choose
the operation and field documentation specific enough to produce valid input.

```rust
#[derive(Default)]
struct PortfolioApp;

impl DynAomiTool for GetPortfolio {
    type App = PortfolioApp;
    type Args = GetPortfolioArgs;

    const NAME: &'static str = "get_portfolio";
    const DESCRIPTION: &'static str = "Read token balances for one address.";

    fn run(
        _app: &PortfolioApp,
        args: GetPortfolioArgs,
        ctx: DynToolCallCtx,
    ) -> Result<Value, String> {
        // Validate args, call the declared host capability, and return JSON.
        todo!()
    }
}
```

Register the App once in `src/lib.rs`:

```rust
const PREAMBLE: &str = include_str!("preamble.md");

aomi_sdk::dyn_aomi_app!(
    app = PortfolioApp,
    name = "portfolio",
    version = "0.1.0",
    preamble = PREAMBLE,
    tools = [GetPortfolio],
    namespaces = ["evm_token_holdings"],
);
```

## Choose the right execution boundary

Return ordinary JSON for a completed read or calculation. Use an async tool
when work must emit progress. Use `ToolReturn` routes when a result supplies
host-managed data for a follow-up step.

For transaction workflows, use the Pipeline host capabilities to build and
simulate a typed operation. Let the runtime create a durable Action for user
review and signing. A route is a continuation hint and does not bypass policy
or approval.

## Handle credentials

Declare service configuration as an operator-owned `Secret`. Mark a credential
that each user supplies with `.user_owned()` and resolve it only from the
current `DynToolCallCtx`. Never place a secret value in a tool result, log, or
preamble.

## Build and verify

Run the SDK toolchain from the App directory:

```bash
cargo install aomi-sdk --locked --features cli,dev-runtime
aomi build
aomi run --port 8081
```

Exercise each tool with valid and invalid inputs before packaging. Test routed
returns as full `ToolReturn` values so route names, bindings, and callback
artifacts remain part of the contract.
