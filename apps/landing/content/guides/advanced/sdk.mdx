# Advanced Rust SDK patterns

The public plugin interface is `aomi-sdk`. Build on `DynAomiTool` and register
the plugin with `dyn_aomi_app!`; backend runtime builders and private runtime
crates are not plugin APIs.

## Async work

Set `IS_ASYNC = true` and implement `run_async` when a tool needs to report
progress. `DynAsyncSink::emit` publishes a non-terminal JSON update.
`complete` or `fail` ends the call, and `is_canceled` lets expensive work stop
after cancellation.

```rust
impl DynAomiTool for BuildReport {
    type App = ReportsApp;
    type Args = ReportArgs;

    const NAME: &'static str = "build_report";
    const DESCRIPTION: &'static str = "Build a report and stream progress.";
    const IS_ASYNC: bool = true;

    fn run_async(
        _app: &ReportsApp,
        args: ReportArgs,
        _ctx: DynToolCallCtx,
        sink: DynAsyncSink,
    ) -> Result<(), String> {
        sink.emit(json!({ "stage": "collecting" }))
            .map_err(|error| error.to_string())?;
        sink.complete(json!({ "report": args.topic }))
            .map_err(|error| error.to_string())
    }
}
```

Pass bare JSON to progress updates. Only the terminal result may carry a
routed return envelope.

## Routed returns

Override `run_with_routes` to return a `ToolReturn`. `RouteStep::on_return`
suggests an immediate follow-up. A bound route can wait for a named callback
artifact produced by another step.

These routes carry data and ordering. They do not grant permission to execute,
bypass policy, or replace user review. Preserve the host-produced callback
artifact instead of reconstructing signatures, hashes, quote IDs, or route IDs.

## User-owned credentials

Declare user-provided credentials with `Secret::new(...).user_owned()`. Read
them from `DynToolCallCtx` through `resolve_user_secret_value`. The resolver has
no argument or environment fallback, which keeps one user's App credential
inside the authorized invocation that supplied it.

Use the ordinary `resolve_secret_value` helper for operator-owned configuration
that intentionally supports argument, injected-context, and environment
resolution.

## Testing

Use `TestCtxBuilder` to provide state attributes and injected secrets. The SDK
also exposes helpers that invoke `run_with_routes`, so tests can inspect the
full `ToolReturn` and route declarations without a hosted runtime.
