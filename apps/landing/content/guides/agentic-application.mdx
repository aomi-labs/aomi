An **App** is the deployed unit you select in Aomi. Builders author a plugin with tools, a preamble, and declared configuration; activation makes it available as an App.

Auto routing uses the caller's available capabilities. Direct routing selects one App explicitly. Discover available Apps from your environment instead of copying a fixed registry from a guide.

## Select an App

```ts
await aomi.agent.run("Describe the capabilities of this App.", {
  target: { mode: "direct", applicationId: selectedApplicationId },
});
```

This snippet uses the [current client contract](https://aomi.dev/docs/integrate/client-sdk#check-compatibility). The canonical Application ID selects the deployed App. It is distinct from a session ID or a Pipeline catalog slug.

## Authenticate the caller

Guests can use the capabilities allowed by the environment. Account-owned calls use an exact-resource OAuth grant or the host's authenticated session. Browser embeds use an origin-bound widget session. A missing or invalid credential returns `401`; insufficient scope or access returns `403`.

Some Apps declare credentials that each signed-in user supplies. Those values are scoped to that account and App and are never a replacement for OAuth. Read [Apps and authentication](/docs/build/namespaces) before managing them.

Connecting a wallet supplies context and signing capabilities. It does not approve unattended transactions. Review typed Actions, durable Commits, or Pipeline requests before signing.

See [Building Apps](/docs/build/services/building-apps), [API reference](/docs/build/services/api-reference), and the [canonical integration guides](https://aomi.dev/docs/integrate/client-sdk).
