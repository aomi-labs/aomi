# Aomi Rust SDK

[`aomi-sdk`](https://crates.io/crates/aomi-sdk) is the supported Rust API for
building Aomi plugins. A plugin declares an App manifest, a preamble, and typed
tools. The hosted runtime loads that manifest and supplies call context,
credentials, host capabilities, and durable follow-up routing.

The public crate is maintained in the
[`aomi-sdk` repository](https://github.com/aomi-labs/aomi-sdk). Pin the version
you test and package the plugin as a `cdylib`:

```toml
[lib]
crate-type = ["cdylib"]

[dependencies]
aomi-sdk = "=5.1.1"
serde = { version = "1", features = ["derive"] }
```

## Define a tool

Implement `DynAomiTool` once for each operation exposed to the model. Its
argument type is deserialized from JSON and converted into a JSON Schema.

```rust
use aomi_sdk::schemars::JsonSchema;
use aomi_sdk::serde_json::{json, Value};
use aomi_sdk::{DynAomiTool, DynToolCallCtx};
use serde::Deserialize;

#[derive(Default)]
struct GreeterApp;

#[derive(Debug, Deserialize, JsonSchema)]
struct GreetArgs {
    /// Person to greet.
    name: String,
}

struct Greet;

impl DynAomiTool for Greet {
    type App = GreeterApp;
    type Args = GreetArgs;

    const NAME: &'static str = "greet";
    const DESCRIPTION: &'static str = "Greet one person by name.";

    fn run(
        _app: &GreeterApp,
        args: GreetArgs,
        _ctx: DynToolCallCtx,
    ) -> Result<Value, String> {
        Ok(json!({ "message": format!("Hello, {}!", args.name) }))
    }
}
```

Register the App and its tools in `src/lib.rs`:

```rust
const PREAMBLE: &str = "Help the user greet people.";

aomi_sdk::dyn_aomi_app!(
    app = GreeterApp,
    name = "greeter",
    version = "0.1.0",
    preamble = PREAMBLE,
    tools = [Greet],
);
```

## Runtime interfaces

| API                          | Purpose                                                           |
| ---------------------------- | ----------------------------------------------------------------- |
| `DynToolCallCtx`             | Read session attributes and injected secrets for the current call |
| `DynAsyncSink`               | Emit progress and one terminal result from an async tool          |
| `ToolReturn` and `RouteStep` | Return data with host-managed follow-up routes                    |
| `Secret`                     | Declare operator-owned or user-owned credentials                  |
| `TestCtxBuilder`             | Exercise a tool with host-like attributes and secrets             |

`run_with_routes` supports a result plus continuation hints. Routes remain
subject to runtime policy and approval. Use `IS_ASYNC = true` and `run_async`
for work that emits progress through `DynAsyncSink`.

## Credentials

Operator-owned secrets resolve from explicit arguments, injected context, then
the environment. Mark an App credential with `.user_owned()` and read it only
with `resolve_user_secret_value(&ctx, name, missing_message)`. User-owned
credentials are injected for an authorized call and never fall back to an
argument or process environment variable.

Never log, return, or persist a resolved credential value.
